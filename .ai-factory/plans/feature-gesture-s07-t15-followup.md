## Roadmap Linkage

- **Milestone:** add a new entry `S07.5 GestureArena — T15 wiring follow-up` under Phase II (sibling to `S07 GestureArena`, distinct from the merged-S07 milestone tick).
- **Rationale:** S07 shipped the user-visible API plus the paint→dispatch wiring, but five architecturally significant pieces were intentionally deferred to keep the merge size sane (mem::take merge tightening, DoubleTap hold/release, LongPress back-channel, MouseExit semantics, end-to-end test). This PR closes those out and adds the extensibility seam (`RecognizerLifecycle` trait) so future recognizers — Stylus, multi-touch, third-party — slot in without touching `Window::dispatch_event` again.

## Goals

1. **Close the T15.5 backlog from S07** so every public gesture API actually fires through the production dispatch path under all documented scenarios (currently DoubleTap and LongPress both fail end-to-end).
2. **Establish an extensibility seam** — `RecognizerLifecycle` trait + `GestureBinding::register_recognizer` API — so adding a new recognizer is one trait impl + one fluent builder, not a `Window::dispatch_event` patch.
3. **Make `test-support` buildable on Windows** by decoupling it from `wayland`/`x11` platform features. The pre-merge end-to-end integration test was deferred precisely because of this dependency knot; T1 unties it so T10 can land.
4. **Consolidate ownership of gesture state** into `GestureBinding` (no more direct `Window::gesture_sanitizer` + `gesture_pointer_state` fields) so the entire gesture subsystem has one source of truth.
5. **Prevent the next regression** with property-based locks for arena lifecycle invariants (no duplicate PointerIds, `active_pointer_count` never grows unbounded, hold/release symmetry).

## Non-goals

- **Touch / Stylus platform integration.** The recognizer side is ready (`PointerKind::Touch`, `PointerKind::Stylus` already `#[non_exhaustive]`-friendly), but actually emitting these from the platform layer is S20 / a future spec.
- **Spatial-index hit-test.** Linear scan over `SmallVec<[HitboxId; 8]>` is still fine; BVH/quadtree is a P-track perf milestone.
- **Migrating to `tracing`.** Stay on `log` + `kv` — that decision belongs to A4.
- **Public `GestureArenaTeam` registration via `InteractiveElement`.** That belongs to a future `GestureDetector` widget (Layer 3, `flui-widgets`); the trait is ready, the public registration is not in scope here.
- **`GestureRecognizer` trait public extension.** New methods on the trait would be a downstream-breaking change; instead T4 introduces a separate `RecognizerLifecycle` trait with default-empty methods that recognizers opt into. No breakage to existing impls.

## Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Extensibility seam | Separate `RecognizerLifecycle` trait with default-empty methods, not new methods on `GestureRecognizer` | Adding methods to the existing trait breaks all downstream impls. A second trait with `Default::default()`-style empties stays additive. |
| Back-channel ownership | `Weak<RefCell<GestureArenaManager>>` injected at registration, not at construction | Construction time has no `Window` reference; registration time does. Weak lets the recognizer outlive a window-resize/tear-down without dangling. |
| DoubleTap timeout timer | Per-pointer `Task<()>` stored in `GestureBinding`, keyed by `PointerId` | Mirrors the LongPress drop-cancel pattern. Dropping the binding (window close) cancels every in-flight timeout. |
| `test-support` decoupling | Split into `test-support` (test infra only) + `test-support-with-platform` (test infra + wayland/x11 + macOS deps) | Lets Windows CI link against `test-support` without forcing all-platform deps. **Breaking change** documented in CHANGELOG. |
| Window gesture-state ownership | Single source of truth: `GestureBinding`. Direct `Window::gesture_sanitizer` + `gesture_pointer_state` removed. | Eliminates the "shadow field" footgun Copilot review S3 flagged. |
| Per-window settings | Recognizers receive `&GestureSettings` at registration, not at construction | Today fluent builders run inside `render()`, so `GestureSettings::default()` overrides every per-window override. Deferring settings to registration restores the documented `window.gesture_settings_mut()` contract. |

### Phase B — Architectural primitives

- [x] **T3:** Add `GestureBinding::register_recognizer(pointer_id, recognizer)` API. Returns `Rc<RefCell<...>>` with the recognizer-index recorded in the arena entry. Internally injects a `Weak<RefCell<GestureArenaManager>>` back-channel into recognizers that opt into it via T4. Replaces the inline `arena.add(pointer_id, Rc::clone(&rec))` in `Window::dispatch_event`'s Down handler. Foundation for T5 (LongPress) and T6 (DoubleTap).
- [x] **T4:** Define `RecognizerLifecycle` trait in `gesture/recognizer.rs`. Methods (all default-empty): `needs_back_channel(&self) -> bool { false }`, `set_arena_back_channel(&mut self, _back_channel: Weak<RefCell<GestureArenaManager>>, _index: usize) {}`, `needs_arena_hold(&self) -> bool { false }`, `configure_settings(&mut self, _settings: &GestureSettings) {}`. Update existing 5 recognizers to opt in: `LongPress` overrides `needs_back_channel` + `set_arena_back_channel`; `DoubleTap` overrides `needs_arena_hold`; all five override `configure_settings` to read thresholds from the supplied settings. **Dispatch decision (locked):** `GestureRecognizer` gains a default-`None` accessor `fn lifecycle(&mut self) -> Option<&mut dyn RecognizerLifecycle> { None }`. Recognizers that opt in override the accessor to return `Some(self)`. **Why this shape:** (a) no `Any` downcast cost, (b) supertrait would force every existing `GestureRecognizer` impl to also impl the new trait — breaking change to public surface, (c) accessor is one line per recognizer and `None` for stubs / mocks. `RecognizerLifecycle` itself is **not** a supertrait of `GestureRecognizer`; the two are siblings linked through the accessor.

  For the drag family the override is `fn configure_settings(&mut self, settings: &GestureSettings) { self.inner.pan_slop = settings.pan_slop; }` — the private `DragImpl` storage stays private, the trait method just reaches through `inner` like the existing builder methods do.

### Phase C — T15.5 backlog wiring

- [x] **T5:** Wire `LongPressGestureRecognizer.arena_back_channel`. Registration injects the weak handle + index. Timer task (already `cx.spawn`-based) upgrades the weak and calls `arena.declare_winner(pointer_id, index, ...)`. Drop on rejected/cancel cancels via `Task` drop. Add `log::debug!` `kv` events (`recognizer="long_press"`, `phase="timer_fire"|"timer_cancel"`, `pointer_id`, `lifecycle="accept"|"cancel"`). Lock with `#[flui_core::test]` test using `cx.background_executor().run_until_parked()` after sleeping past `long_press_timeout` to verify the callback fires.
- [x] **T6:** Wire DoubleTap arena.hold/release. Dispatcher on `Down` checks `recognizer.lifecycle().map_or(false, |l| l.needs_arena_hold())`; if any registered recognizer for the hit hitbox returns `true`, `arena.hold(pointer_id)` after `arena.add`. After first `Up`, sweep is suppressed. Per-pointer timeout timer (stored in `GestureBinding`'s new `arena_hold_timers: FxHashMap<PointerId, Task<()>>`) fires `double_tap_timeout` later and calls `arena.release(pointer_id)`. **Cancellation paths:** (1) successful second-tap acceptance — dispatcher removes the timer entry from the map (Task drops, future cancels); (2) Cancel/Removed events on the held pointer — `arena.cancel(pointer_id)` runs and the dispatcher drops the timer alongside; (3) recognizer-side rejection — same drop-on-rejected-call. Make sure `GestureBinding::Drop` also drops the map (window teardown cancels every in-flight timeout). Lock with end-to-end test that exercises a real two-tap sequence through arena dispatch and a separate test that cancels mid-hold.
- [x] **T7:** Replace `arena.arenas.extend(live.arenas.drain(..))` in `Window::dispatch_event` with `merge_by_pointer_id`. Implementation in `GestureArenaManager`: for each `(pid, incoming)` in `live.arenas.drain(..)`, find any existing entry with the same `pid` and append `incoming.entries` into it; otherwise push the new entry. **Collision policy** for the per-pointer scalar fields:
  - `entries`: append (incoming entries land at the back, registration-order semantics preserved).
  - `winner`: incoming wins if `Some` (a callback that declared a winner mid-dispatch wins over the outer pre-take state); otherwise keep the existing.
  - `is_open`: `existing.is_open && incoming.is_open` (closing on either side closes the merged arena).
  - `is_held`: `existing.is_held || incoming.is_held` (either side holding holds the merged arena — DoubleTap's hold semantics survive a callback-time merge).

  Lock with proptest property: for any sequence of (mem::take, dispatch, restore) operations, no `PointerId` appears twice in the final `arenas` vec, and the collision policy above is honoured.
- [x] **T8:** `dispatch::convert` translates `MouseExitEvent` to `PointerPhase::Removed`, not `PointerPhase::Exit`. Update unit tests in `dispatch.rs::tests`. Document the distinction in `pointer_event.rs` rustdoc on `PointerPhase`. Confirm `diff_hover` still synthesizes per-target `Exit` events on hover boundary transitions (those are correct as-is).
- [x] **T9:** Per-window `GestureSettings` flow. `__internal_on_*` helpers in `gesture/mod.rs` no longer apply settings at construction; instead `GestureBinding::register_recognizer` calls `recognizer.lifecycle().map(|l| l.configure_settings(self.settings()))` (T4 hook + accessor) before adding to the arena. After this change, `window.gesture_settings_mut().long_press_timeout = ...` actually affects every recognizer created via the fluent builders. **Drag family note:** the `inner: DragImpl` private storage is still the canonical settings home; `configure_settings` for drag types just sets `self.inner.pan_slop = settings.pan_slop`. The existing `with_pan_slop` builder still works as an explicit override (it sets `inner.pan_slop` directly, after registration). Lock with a new behaviour test: paint, override `long_press_timeout`, simulate Down/timer/Up, verify the callback timing matches the override.

## Risks

- **Test-support split (T1)** is a workspace-wide change. Downstream crates that depend on `test-support` and rely on wayland/x11 transitively will need to migrate. **Already-known consumer:** `flui-navigator/Cargo.toml:28` — handled by T1.1, blocks Phase A from advancing without it. Mitigation: explicit `test-support-with-platform` feature + CHANGELOG entry + migration note in T13 docs + `cargo hack check --feature-powerset --depth 2` smoke entry in T1.
- **DoubleTap hold/release wiring (T6)** introduces a per-pointer timer Task in `GestureBinding`. If the timer task panics or leaks, the arena holds forever for that pointer. Mitigation: `Drop` semantics on `Task<()>` cancel the future; explicit `arena.release` in `cancel` path drops the timer too.
- **`RecognizerLifecycle` trait (T4)** is a long-lived public-ish surface. Renaming methods later breaks downstream impls. Mitigation: small surface (4 default methods), all `#[non_exhaustive]`-friendly, named after Flutter analogues so they survive an A4-style rewrite.
- **Per-window settings flow (T9)** changes the timing of when recognizer thresholds are applied. Existing user code that sets thresholds *after* construction (e.g. `tap.touch_slop = ...` after `on_tap(...)`) keeps working — the change only affects the *initial* values. Mitigation: rustdoc explicitly states "fluent builders read settings at registration time, mutating fields post-construction overrides".
- **LongPress timer back-channel via Weak (T5)** can race with window teardown. If the timer fires after the window is dropped, the `Weak` upgrade returns `None` and the call is a no-op. Lock with a regression test that drops the window between Down and timer fire.
- **Recognizer construction-time settings reads stay until T9 lands.** Until T9, fluent-built recognizers still ignore `window.gesture_settings_mut()`. Mitigation: T9 lands in the same commit checkpoint as T5/T6/T7/T8 so the user-facing contract holds at every checkpoint.
