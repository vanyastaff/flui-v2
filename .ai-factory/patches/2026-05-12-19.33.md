# derive(Widget) silently accepted malformed #[widget(...)] attributes

**Date:** 2026-05-12 19:33
**Files:** crates/flui-macros/src/derive_widget.rs, crates/flui-framework/tests/widget_derive/{fail_widget_empty_attr.rs,fail_widget_empty_attr.stderr,fail_widget_unknown_subarg.rs,fail_widget_unknown_subarg.stderr}, crates/flui-framework/tests/widget_derive_compile.rs
**Severity:** medium

## Problem

Two attribute-parsing edge cases produced silent / misleading behavior in `#[derive(Widget)]`:

1. **`#[widget()]` (empty meta list)** was treated as if the user wrote `#[widget(key)]`. The field's `Widget::key` got the override implementation generated, plus the `Option<Key>` type check still ran. A user who forgot the `key` argument got the key semantics without writing it — or got a misleading "must be `Option<Key>`" error on a non-`Option<Key>` field they never marked as a key. No diagnostic indicated the empty parens were the actual issue.

2. **`#[widget(key, <unknown>)]`** was silently ignored. The user wrote what they thought was a valid key marker (with a typo in the second sub-argument), but the entire attribute was treated as if it didn't exist. No `fn key` override generated, no error message — just the trait default `None` returned at runtime with no hint that the user's annotation was the cause.

Both bugs were surfaced by `/aif-review` (suggestions S1 + S2 on commit `2f79de56b3`) and not caught by the T0.2 / T6.2 reviewer triples (which focused on higher-level design questions and missed the macro-attribute-parsing edge cases).

## Root Cause

`has_widget_key_attribute` used `attr.parse_nested_meta(closure).is_ok()` as the gate:

```rust
attr.parse_nested_meta(|meta| {
    if meta.path.is_ident("key") {
        Ok(())
    } else {
        Err(meta.error("expected `key`"))
    }
})
.is_ok()
```

Two semantic mismatches between the gate and the user's intent:

- `parse_nested_meta` calls the closure **once per comma-separated meta item**. For empty parens `#[widget()]` there are zero meta items, so the closure runs zero times and `parse_nested_meta` returns `Ok(())`. The `.is_ok()` check then says "true — this is a `#[widget(key)]` attribute" even though `key` was never seen.
- When the closure returns `Err` for an unknown sub-argument, `parse_nested_meta` short-circuits and returns `Err`. The `.is_ok()` check converts that error into a silent `false` — the diagnostic the closure carefully constructed (`meta.error("expected `key`")`) never reaches the user.

In short: the bool-cast threw away both the "did we see what we wanted?" signal and the diagnostic content of any closure error.

## Solution

Refactored the helper into `check_widget_key_attribute(&Attribute) -> syn::Result<bool>` with three explicit outcomes:

- `Ok(false)` — the attribute is not `#[widget(...)]`; caller skips it.
- `Ok(true)` — the attribute is exactly `#[widget(key)]`; mark the field.
- `Err(...)` — the attribute IS `#[widget(...)]` but malformed; propagate the error.

```rust
fn check_widget_key_attribute(attr: &syn::Attribute) -> syn::Result<bool> {
    if !attr.path().is_ident("widget") {
        return Ok(false);
    }

    let mut seen_key = false;
    attr.parse_nested_meta(|meta| {
        if meta.path.is_ident("key") {
            seen_key = true;
            Ok(())
        } else {
            Err(meta.error("unknown #[widget(...)] argument; expected `key`"))
        }
    })?;

    if !seen_key {
        return Err(syn::Error::new_spanned(
            attr,
            "#[widget(...)] requires the `key` argument; write `#[widget(key)]`",
        ));
    }

    Ok(true)
}
```

`locate_key_field` updated to propagate `?` instead of bool-checking. The fix is structurally minimal — same logic shape, just preserves the Result chain.

Two new trybuild fixtures lock the diagnostics:

- `tests/widget_derive/fail_widget_empty_attr.rs` + matching `.stderr` — `#[widget()]` produces `"#[widget(...)] requires the key argument; write #[widget(key)]"` with span on the whole attribute.
- `tests/widget_derive/fail_widget_unknown_subarg.rs` + matching `.stderr` — `#[widget(key, oops_typo)]` produces `"unknown #[widget(...)] argument; expected key"` with span pointing at `oops_typo`.

The unused `Field` import in `derive_widget.rs` was removed (the new helper takes `&Attribute`, not `&Field`).

## Prevention

For future proc-macros in this project:

1. **Never use `.is_ok()` to gate on `parse_nested_meta`.** The bool throws away both the "was the requirement actually met?" and the diagnostic content. Prefer returning `syn::Result` from helpers and propagating with `?`.

2. **For "this argument MUST appear" requirements, track an explicit `seen_*` flag** alongside `parse_nested_meta`. The closure runs zero times for empty meta lists, so you cannot rely on the closure-was-called signal alone.

3. **Add a compile-fail trybuild fixture for each attribute syntax variant the macro is expected to reject.** Empty parens, unknown sub-args, malformed types, multiple-key collisions — every category should have a snapshot. The reviewer triple in T0.2/T6.2 missed these because the existing fixtures only covered well-formed (or known-malformed-type) inputs.

4. **Code review pattern:** when reviewing a proc-macro PR, mentally enumerate the truth table for the attribute parser:
   - `#[name]` (just the attribute, no args)
   - `#[name()]` (empty meta list)
   - `#[name(expected)]` (canonical form)
   - `#[name(unexpected)]` (unknown sub-arg)
   - `#[name(expected, unexpected)]` (canonical + unknown)
   - `#[name(expected, expected)]` (duplicate sub-arg)
   - `#[name = "value"]` (name-value form when list form was expected)
   - Each should produce a deterministic, diagnostic-bearing outcome — either accept or error with a clear message.

5. **`#[non_exhaustive]` mindset for attribute parsers.** Treat each accepted sub-argument as opt-in via an explicit allowlist. Anything not on the list is an error. SF02+ macros that need additional `#[widget(...)]` sub-args (e.g., `#[widget(global)]`, `#[widget(ignore_for_keying)]`) should add them to the allowlist explicitly, not extend implicitly.
